이 과정의 강점 여섯 가지

교육멘토님이 상담에서 길게 설명하지 않아도 되도록, 강점마다 근거를 같이 적었습니다.

목표가 「많이 배웠다」가 아니라 「배포했다」입니다

수료 시점에 공개 URL로 열리는 앱, 테스트 10건 결과표, README, 데모 영상이 남습니다.

근거: 캡스톤 Basic이 수료선입니다. 결과물 중심 평가라서 면접에서 「이걸 만들었다」고 바로 보여줄 수 있습니다.

눈(컴퓨터비전)과 말(LLM)을 한 과정에서 연결합니다

같은 사진을 전통 컴퓨터비전과 Vision LLM으로 각각 풀어 보고 정확도·속도·비용을 비교하는 실험이 과정의 핵심 장면입니다. 어느 한쪽만 배우면 보이지 않는 선택 기준이 생깁니다.

근거: 대구·경북 채용공고는 제조·머신비전 비중이 높고, LLM·에이전트 공고는 별도로 많습니다. 두 갈래를 모두 커버합니다.

저녁반 체력에 맞춰 일부러 줄였습니다

모든 일차를 같은 무게로 두지 않고 네 가지로 나눴습니다. 대부분은 직접 구현하는 Core, 일부는 택1 또는 심화인 Track, 일부는 강사 시연인 Demo, 나머지는 수료 후 자료로 넘긴 Further입니다. 비중은 기술 변화와 수강생 진도에 맞춰 유연하게 조정합니다. 하루에 새 도구는 하나, 새 개념은 최대 2~3개입니다.

근거: 하루 3시간 × 60일 = 180시간 안에서 내용을 덜어 내고, 대신 결과물을 만드는 시간을 확보했습니다.

결석해도 돌아올 수 있습니다

수업 녹화본을 제공하고, 결석한 수강생이 따라올 수 있도록 스타터 코드도 함께 줍니다. 정리 시간은 특정 날짜에 정해 두지 않고, 수강생 진도에 맞춰 상황에 따라 운영합니다. 결석한 분이 흐름을 놓치지 않도록, 강사는 수업 자료로 길을 열어 두고 교육멘토님은 수강생과의 소통으로 곁에서 챙겨 주시면 서로 합이 잘 맞을 것 같습니다.

근거: 이직자·재직자가 섞인 저녁반은 결석이 잦다는 전제에서 설계했습니다. 이탈 방지는 이 과정의 설계 목표입니다.

채용공고에서 거꾸로 설계했습니다

공고에 자주 나오는 FastAPI와 Docker는 넣고, 상대적으로 드문 MCP는 체험 수준으로 줄였습니다. 도구 이름이 아니라 「입력 → 전처리 → 모델 → 평가 → 서비스」 흐름을 단계마다 반복하기 때문에 도구가 바뀌어도 쓸 수 있습니다.

근거: 강사가 직접 수집한 공고 샘플 기준(아래 「채용 시장 근거」 참고).

범용 챗봇이 아니라 도메인 문제를 풉니다

PDF 챗봇 같은 흔한 데모는 지양합니다. 수강생이 가진 업무·전공 문제를 캡스톤 주제로 잡고, 테스트 10건, 실패 사례 공개, 모델 선택 근거, 개인정보·저작권·모델 라이선스 점검까지 문서로 남깁니다. AI 코딩 도구를 쓰되 생성된 코드도 같은 테스트를 통과해야 합니다.

근거: 채용 담당자가 범용 챗봇 포트폴리오에 피로감을 느낀다는 점이 강사의 설계 원칙입니다.

유동적으로 운영합니다 아래 구성은 기준안입니다. 이 과정은 기술 변화가 빨라서 되도록 지키되, 최신 동향과 수강생의 진도·환경에 맞춰 단계별 일수와 내용을 유연하게 조정합니다. 일수는 대략적인 비율로 봐 주세요.

수료하면 무엇이 남나

캡스톤은 개인 프로젝트가 기본입니다. 결석 위험이 있는 수강생은 역할을 나눈 2인 팀도 선택할 수 있습니다. 합격선을 세 단계로 나눠서 전원이 수료선에 닿게 하고, 더 가고 싶은 사람은 올라가게 했습니다.

Basic · 수료선Streamlit 앱 공개 배포, 테스트 10건 결과표, README, 데모 영상. 전원 도달이 목표입니다.
StandardBasic에 FastAPI로 만든 API를 더합니다. 취업용으로 권장합니다.
AdvancedStandard에 Docker 실행(또는 Codespaces 실행 가이드)과 선택 기술을 더합니다.

상담 포인트: 「Docker가 어려워서 못 따라가면 어쩌죠?」라는 질문을 받으면 교육멘토님은 수료선에 포함되지 않는다고 안내해 주시면 됩니다. 한 명의 환경 문제가 반 전체의 진도를 멈추지 않게 분리해 둔 설계입니다.

채용 시장 근거

커리큘럼을 정하기 전에 강사가 채용공고를 직접 모아 살펴봤습니다. 교육멘토님이 상담 자료에 인용하실 때는 「강사가 확인한 공고 샘플 기준」이라고 밝혀 주세요.

36%LLM·에이전트 공고 12건 상세 분석 중 FastAPI를 요구한 비율
45%같은 12건 중 Docker를 요구한 비율
9%같은 12건 중 MCP를 요구한 비율. 그래서 체험 수준으로만 다룹니다
  • 수집 규모: 대구·경북 공고 15건, LLM·에이전트 공고 28건(12건 상세 분석), 컴퓨터비전 공고 16건.
  • 대구·경북 공고는 제조·머신비전 중심이라 컴퓨터비전에 충분한 비중을 유지하고, 세그멘테이션·영상 분석과 OCR·문서 추출 중 하나를 고르는 Track을 두었습니다.
인용 주의 표본이 작아서 시장 전체 통계가 아닙니다. 교육멘토님은 「채용 시장의 36%가 FastAPI를 요구한다」처럼 일반화해서 말하지 마시고, 공고 샘플에서 반복해서 보인 기술이라고 표현해 주세요. 취업을 보장하는 표현도 쓰지 않습니다.

수강생별 어필 포인트

교육멘토님의 상담 첫 질문은 「이 과정으로 무엇을 하고 싶으세요?」를 권합니다. 취업 준비와 업무 자동화는 목표가 달라서, 한 번에 둘 다 약속하면 기대가 어긋납니다.

예상 질문과 답변

비전공자도 따라갈 수 있나요?

Python 기초 문법을 아는 분이라면 가능합니다. 사전 영상(5~6시간)을 개강 전에 이수하는 것이 조건입니다.

교육멘토님은 「누구나 가능」이라고는 말하지 않는 것이 좋습니다. 이미지 데이터를 다루는 구간은 난이도가 있어서, 그림을 먼저 보여 주고 코드는 최소로 시작하는 방식으로 완충합니다.

하루 3시간에 이걸 다 하나요?

다 하지 않습니다. 직접 구현하는 Core, 택1인 Track, 강사 시연인 Demo, 수료 후 자료인 Further로 나눠 두었습니다. 수료에 필요한 것은 Core 과제와 캡스톤 Basic입니다.

중간에 결석하면 따라갈 수 없지 않나요?

수업 녹화본을 제공하고, 결석한 부분을 따라올 수 있도록 스타터 코드를 줍니다. 정리 시간은 특정 날짜에 고정하지 않고 수강생 진도에 맞춰 운영합니다. 결석한 분을 챙기는 일은 강사의 수업 자료와 교육멘토님의 소통이 함께 맞물릴 때 가장 효과가 큽니다.

컴퓨터비전과 LLM을 둘 다 하면 얕아지지 않나요?

깊이를 연구가 아니라 활용에 둡니다. 모델을 처음부터 학습시키지 않고, 사전학습 모델을 골라 쓰고, 결과를 평가하고, 서비스로 붙이는 데까지를 반복합니다. 두 기술을 같은 문제에 적용해 비교하기 때문에 오히려 선택 기준이 남습니다.

GPU가 없는 노트북인데 괜찮나요?

GPU가 없어도 수강할 수 있도록 수업을 구성합니다. 모델을 직접 학습시키지 않고 사전학습된 모델과 API를 활용하는 방식이라 고사양 장비를 전제로 하지 않습니다. 실습 환경은 진행하면서 상황에 맞춰 유연하게 대처합니다.

취업이 되나요?

취업을 보장하는 과정은 아닙니다. 수료 시 공개 배포된 앱, 테스트 결과표, README가 포트폴리오로 남고, 채용공고에서 반복되는 기술을 실제로 써 본 경험을 설명할 수 있게 됩니다.

API 비용이나 준비물이 따로 드나요?

실습에서 LLM API를 사용하기 때문에 이용료가 조금 발생할 수 있습니다. OpenAI나 Anthropic 같은 서비스의 API 키 결제가 필요할 수 있고, 어떤 서비스를 쓰는지는 수업 상황에 따라 달라집니다. 구체적인 준비물과 비용은 진행하면서 상황에 맞춰 유연하게 정합니다.

「무료」나 「추가 비용 없음」이라고는 안내하지 말아 주세요.

다른 AI 과정과 무엇이 다른가요?

교육멘토님은 세 가지로 답하시면 됩니다. 첫째, 수료 목표가 배포된 결과물입니다. 둘째, 컴퓨터비전과 LLM을 한 과정에서 비교하며 배웁니다. 셋째, 저녁반 수강생을 위한 이탈 방지 구조(수업 녹화본, 스타터 코드, 진도에 맞춘 정리)가 있습니다. 다른 기관 과정의 내용을 단정해서 비교하지는 말아 주세요.

1분 버전

이 과정은 AI를 많이 배우는 과정이 아니라 하나를 끝까지 배포하는 과정입니다. 하루 3시간씩 60일, 총 180시간이고, 컴퓨터비전과 LLM을 같은 문제에 적용해 비교하면서 서비스를 만듭니다. 직장 다니면서 듣는 분이 많아서 결석하면 따라올 수 있게 수업 녹화본과 스타터 코드를 제공하고, 마지막 약 3주는 본인이 고른 주제로 캡스톤을 만듭니다. 변화가 빠른 분야라서 구성은 되도록 지키되 상황에 맞춰 유연하게 조정합니다. 수료하면 배포된 앱과 테스트 결과표, README가 남습니다.

과정명 활용 팁 과정명에 컴퓨터비전이 드러나지 않습니다. 교육멘토님은 상담에서 「LLM 서비스 개발 과정이고, 사진·영상·문서를 다루는 컴퓨터비전도 함께 다룬다」를 먼저 말씀해 주세요. 컴퓨터비전이 이 과정의 차별점이기 때문입니다.
